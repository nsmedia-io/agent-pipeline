# pipeline

A risk-tiered multi-agent development pipeline for Claude Code. It turns a one-line ask into a validated spec, a single-writer implementation with tests, and an adversarial review panel on the finished diff, with typed artifacts at every step and a plain file-based knowledge store (no external services).

## The idea

Multi-agent spend goes where independence actually pays:

- **The write path is single-threaded and carries full context.** One Dev thread receives the spec, the blast-radius map, and the specialists' constraint checklists, then writes code and its tests together. Fragmenting planning, review, and implementation across contexts loses more than it gains.
- **Independent review of a finished artifact fans out.** A panel of agents reviews the finished diff concurrently, each through a distinct lens (spec fidelity, security, testing, code quality, data, infra), while remote CI runs in parallel: local checks are the implementation done gate, and remote CI-green is a merge precondition verified at merge, not a panel-entry gate. Fresh eyes on a fixed diff catch what the author cannot. When the panel requests changes, the re-run is a delta re-review: QA and SecOps re-review unconditionally, plus the objecting and surface-touched roles, additively merged so standing approvals hold and the final verdict is computed over the full panel.
- **Phases are quality gates with loop-backs, not a waterfall.** A later phase that invalidates an earlier assumption loops back to the owning phase.

## Install

```
/plugin marketplace add nsmedia-io/agent-pipeline
/plugin install pipeline@agent-pipeline
```

Then, in any project:

```
/pipeline <your ask>            # run the full pipeline
/pipeline --resume <id>         # resume a halted run
/pipeline --issue <n>           # start from an existing tracker issue
/phase <name> --issue <n>       # run a single phase (retry / targeted re-review)
/warmup                         # git status + knowledge highlights, then stand by
```

The orchestrator dispatches these subagents (they never call each other; only the main session orchestrates):

| Agent | Role |
|---|---|
| **BA** | Gatekeeper. Validates the ask, maps blast radius, writes the spec, sets the risk tier. |
| **Dev** | Single Phase 3 implementation thread. Writes code and tests together (or implements QA's failing test contract at the architectural tier). |
| **QA** | Owns the test-discipline standard; renders the binding independent test verdict on the finished diff. |
| **SecOps** | Security and compliance review. Holds the veto. On every panel. |
| **DBA** | Data model, migrations, query safety. Conditional. |
| **DevOps** | Infra, CI/CD, deploy safety. Conditional. |
| **Design** | Frontend/UX/accessibility/copy. Conditional (frontend diffs only). |
| **Art Director** | Owns the RESULT of a visual surface, not its conformance. Authors a binding visual contract before implementation, rules on the gap after. Conditional (only when a contract exists). Its `REQUEST_CHANGES` binds solely on a cited clause plus its own rendered evidence; preference stays advisory. |
| **Librarian** | Post-merge knowledge persistence. Writes the file-based knowledge store. |

## Risk tiers (set by BA, they change the pipeline's shape)

- **trivial**: typo / one-line fix. Straight to a single Dev thread, then a trimmed panel of QA plus SecOps (plus Design on frontend diffs).
- **standard**: a normal feature or bugfix. The specialists' standing constraint checklists are injected into one Dev thread (no pre-code review, and the blast-radius map is folded into the BA intake rather than a separate dispatch); a trimmed panel reviews the diff, with a hard tripwire if migration/auth/contract-shape work appears.
- **architectural**: schema/data-migration, a cross-cutting contract change, a compliance dimension, or a change to the security posture (a new auth flow or authorization check, crypto, webhook verification, a new external data intake, a new retained data type). Reading or writing user data under existing auth is standard. Adds the parallel pre-code review, a design bake-off (two sketches with opposing assigned stances, one judge), the design-lock owner gate, a QA-first failing-test contract, the full panel, and the live-verification gate.

## The knowledge store (file-based, replaces a vector DB)

Durable project knowledge lives as plain JSON in your project's `knowledge/` folder, versioned in git, no embeddings, no network. The Librarian writes it at Phase 5; warmup and the agents read it. See [`knowledge/README.md`](knowledge/README.md).

## Customize (grep the plugin for `CUSTOMIZE`)

Copy `pipeline.config.example.json` to `pipeline.config.json` at your project root. Keys:

| Key | What it does | Default |
|---|---|---|
| `integrationBranch` | Base branch for worktrees and diffs | `main` |
| `checkCommand` | The command Dev and the Stop hook run to prove green. Set it: the fallback is much weaker than it looks | `npm run typecheck`, and only if your package.json declares that script; otherwise the Stop hook verifies nothing at all |
| `knowledgeDir` | Where the knowledge store lives | `knowledge` |
| `frontendSurface` | Globs that mark a diff as frontend-touching (drives the Design lens + visual gate) | a generic component/style set |
| `migrationGlobs` | Globs the pre-Phase-4 gate uses to DISCOVER migrations in the impl-report. REPLACES the built-in preset union, so setting it NARROWS gate discovery. It does NOT narrow the mis-tier tripwire, which unions the same key with the presets; widen both with `extraMigrationGlobs` instead | the fifteen-row framework-preset union in `scripts/data-layer-surface.mjs` |
| `extraMigrationGlobs` | Additive globs that union into gate discovery, the mis-tier tripwire, and the DBA panel seat. Never replaces anything | `[]` |
| `dataLayerGlobs` | Broad globs that seat DBA on the Phase 4 panel (schema, queries, policies, generated DB types). Empty or invalid means defaults | the tripwire union plus the broad extras in `scripts/data-layer-surface.mjs` |
| `infraGlobs` | Globs that seat DevOps on the Phase 4 panel (CI, deploy scripts, infra config). Empty or invalid means defaults | the infra set in `scripts/data-layer-surface.mjs` |
| `migrationDownMarker` | The line that marks a migration's down section for the reversibility gate | `-- DOWN` |
| `dispatchModels` | Per-role model overrides for the orchestrator's dispatches, allowlisted to `opus`/`sonnet`/`haiku`. `secops` and `qa` are pinned to opus in code and ignore this key | the built-in table in `scripts/dispatch-model.mjs` (DBA drops to sonnet on a standard or trivial panel) |
| `dispatchEfforts` | Per-role effort overrides (`low`..`max`) for the Phase 4 panel, which dispatches through the Workflow tool. Every role is reachable, both directions | the tiered table in `scripts/dispatch-effort.mjs` (SecOps xhigh/high/medium and QA high/medium/medium by tier) |
| `securitySurfaceGlobs` | Additive globs that re-seat SecOps on a Phase 4 DELTA round when a fix commit touches them (auth, session, crypto, secrets, webhooks, policies). Widen-only | the built-in set in `scripts/security-surface.mjs` |
| `architecturalTriggers` | Paths/domains/keywords that force the architectural tier | pipeline.config.json, the compliance domain, and the concrete security/data triggers in agents/ba.md duty 6 |

### Upgrading

Thirty-three changes in this release alter BEHAVIOUR on an existing project at its next plugin update, with no action on your part. There is no migration to run; there are thirty-three things to know.

1. **The migration/data-layer/infra glob defaults are now a fifteen-row framework-preset union** (Rails, Django, Alembic, Prisma in both layouts, Drizzle, Supabase in both workflows, Flyway, Liquibase, EF Core, Laravel, plus the generic declarative dumps), **and the mis-tier tripwire can no longer be narrowed by config.** `migrationGlobs` unions with those presets for the tripwire, so a vendored or fixture path under a `migrations/` directory that never halted a run before now WILL, once per path, loudly and recoverably. Widen with `extraMigrationGlobs`; narrowing the tripwire is deliberately impossible, because a halting control bound to a narrowing knob can be disarmed by a four-character edit that reads as tuning. A Markdown docs path is excluded from the narrow set in code, so a `.md`/`.mdx` file under `migrations/` does not halt. Any other extension there does, including `.txt` and images: the exclusion is two extensions, not a notion of "documentation", and it stays that way deliberately. Chasing further spellings would put the guard on the wrong side of the transformation, and the halt it produces is loud, once-per-path, and recoverable.
2. **Editing `pipeline.config.json` now forces the architectural tier.** That file decides whether the tripwire fires, who sits on the Phase 4 panel, and which model renders a binding verdict, so a diff touching it gets the pre-code SecOps review.
3. **If you copied the example config, DELETE its `migrationGlobs` line.** The example used to ship `"migrationGlobs": ["**/migrations/**"]`, and that key REPLACES the preset union for the pre-Phase-4 gate's discovery. Left in place, the gate discovers nothing for a Rails, Alembic, EF Core, Drizzle, declarative-Supabase or Flyway layout while the tripwire still fires: the pipeline re-tiers the change as a migration and then runs a reversibility check over zero files. Set `migrationGlobs` only when you specifically want to narrow gate discovery.

4. **The pre-Phase-4 gate now REFUSES a down region that is executable SQL, or that carries an unterminated block comment**, where it previously accepted any region carrying the marker string. It classifies everything after the marker LINE in one left-to-right scan; block comments do not nest there, and a `/*!` or `/*M!` opener is refused outright because MySQL/MariaDB execute those bodies. The refusal is bounded to migrations the current change adds or touches, never a project's existing backlog. TWO COSTS, named separately because one does not cover the other. First, MySQL's `# line comment` syntax is not recognised as a comment (it is not one in PostgreSQL, SQLite, Oracle or T-SQL), so a project whose down regions use `#` has EVERY such line refused: the remedy is a per-line substitution to `--` across the migrations this pipeline touches, NOT a one-line edit. Second, and separately, the gate now classifies from the END of the marker line, which makes a non-comment MARKER such as `# DOWN` safe; that does nothing for a down BODY written in `#` line comments, which is the first cost above.

5. **`phase_elapsed_ms` is now keyed by the phase each event CLOSED, not the one it was previously read as opening.** `events[]` entries are exit markers (each carries the verdict of the phase it closes), so every figure was shifted one slot and the final phase of every run received no key at all. Figures in `status.json` records written by 0.21.0 or earlier were computed under the old convention and are NOT automatically recomputed: treat them as historical and stale rather than migrating them. Read the new `attribution` field to tell which convention a block was computed under — its absence means the old one.

6. **A turn can now be REFUSED at its end.** `hooks/stop.sh` runs a phase-entry guard: if `status.json`'s `current_phase` names a phase whose prerequisite artifact is absent, and the run is still in flight, the turn is blocked with a message naming the phase, the missing prerequisite and the issue directory. This is the one place the plugin is deliberately fail-CLOSED on its decision, and `CLAUDE_HOOK_STOP_SKIP=1` does NOT bypass it, because a halting control with an opt-out knob is not a halting control. THREE THINGS BOUND IT so it cannot wedge you. It only evaluates a run that is in flight (`updated_at` within `IN_FLIGHT_MS`, and no `final_verdict`), so an abandoned or concluded run never blocks a project. That predicate is not restated here or anywhere else: `scripts/run-candidates.mjs` owns it, and `scripts/pipeline-status.mjs`'s "possibly stuck" filter reads the same function, so the reporter and the guard cannot disagree about the window (#74). `final_verdict` means the run concluded and not merely that it concluded once, because the checkpoint that enters `4-review` for a delta round clears it (#110). Its refusal always names a clearance route: produce the artifact, record a `SKIPPED` deviation with a non-empty note in `events[]`, or conclude the run. And it stays fail-OPEN on TOOLING: if node or the guard script is missing the turn proceeds, and the session-start warmup says so once per session, because a missing install is your environment rather than the orchestrator exercising discretion. What it does NOT do: it fires at the turn BOUNDARY, not before a dispatch, so it cannot make skipping a phase impossible. It makes an unrecorded skip become either a blocked turn or a recorded, reasoned one.

7. **Review can now STOP ITSELF instead of looping.** After the SECOND Phase 2 round returns any `REQUEST_CHANGES`, the orchestrator no longer loops back by default: it halts and puts **split / defer / proceed** to you with a recommendation. A third round happens because you chose it. Paired with this, BA must justify or propose a split once a spec crosses **10 requirements or 12 acceptance criteria**. Neither is a hard limit and neither refuses correct work; both exist because every loop-back is individually justified, so a spec can round-trip indefinitely while each round looks like the gate working. Measured on one run before this change: three Phase 2 rounds, four spec revisions, an 86KB spec that grew to 95KB while its substance halved, and zero lines of code, with every blocker in every round real. If your runs never reach a second `REQUEST_CHANGES` round, you will never see this.

8. **`events[].verdict` and `flags[].verdict` are now capped at 32 characters, and `commands/pipeline.md` restates that cap as a writer rule.** Write the verdict TOKEN and nothing else; reasoning belongs in `summary` or `note`. Be clear about what this is: `status.json` is validated against `status.schema.json` by NOTHING (the file is in no `AGENT_RULES` entry, and that walker does not implement `maxLength` at all), so the cap refuses nothing at write time. It is enforced by a new corpus-conformance suite that walks every committed `.pipeline/*/status.json` on every pull request and reddens if any stored verdict exceeds the cap read FROM the schema. So this detects rather than prevents, and it detects before the record reaches your integration branch. No committed record is invalidated: the longest verdict that exists, declared or observed, is `APPROVE_WITH_NOTES` at 18 characters. The sibling free-text fields (`events[].note`, `veto_reason`, `error`) are deliberately NOT capped, because a length bound would refuse their correct work; the exposure question for those is tracked separately.

9. **The phase-entry guard now ABSTAINS on a tier it cannot determine, instead of applying the strictest row.** Previously an absent, null or malformed `risk_tier` normalised to `architectural`, which switched on the `1-ba` row and demanded a `map.json` that the standard and trivial tiers never produce separately. Because `risk_tier` is BA's output and `1-ba` is checkpointed BEFORE BA is dispatched, the tier is necessarily absent on a run's first visit there, so **the guard refused turn one of most runs**, and the honest clearance route its own message named did not exist at two of the three tiers. It now treats a tier-restricted row as not applying while the tier is undetermined. **What this costs, stated plainly: the `1-ba` map requirement is retired on the mandated path at EVERY tier, not narrowed.** Measured across 75 phase-by-tier combinations, exactly two change, both at `1-ba`. Re-siting that requirement where the tier IS resolved is tracked separately.
10. **The pre-Phase-4 gate's up-section and acceptance-criteria coverage checks are both stricter.** The up-section test was a line-prefix match, so a fully block-commented region counted as present; the coverage matcher passed on token overlap between a criterion and a requirement check. Both said yes too easily. **A change that passed this gate before may now fail it**, which is the intended direction: these are the checks standing between a half-written artifact and the review panel.
11. **Absolute filesystem paths are redacted when a run is archived into the knowledge store.** `archiveIssue` now rewrites by value SHAPE across the whole document, keys included: paths under the repo root become repo-relative, everything else becomes `<redacted-absolute-path>`. This exists because `tasks.json` and `impl-report.json` both carry `worktree_path` absolutely and the archive is committed, so a developer's home directory was reaching a public tree. The predicate replaces the path SPAN and not the whole value, so a descriptive string like `/tmp/x (detached at abc123)` archives as `<redacted-absolute-path> (detached at abc123)`: the path goes, the evidence around it stays (#59).
12. **An mtime tie when resolving which run a session owns now yields NO subject, rather than whichever directory `readdir` returned first.** A fresh `git clone` writes every tracked `status.json` inside one coarse clock tick on Linux, so all of them share an mtime and the old behaviour picked a run by filesystem order. The guard now abstains, which lands on its existing fail-open tooling branch. Combined with item 9, the guard has three distinct ways to produce no decision; they are enumerated in its own header comment so the next person adding a fourth can see the first three.
13. **The orchestrator's `surface_probe` now passes its two arguments in brace form (`"${1}" "${2}"`), in both definitions.** This is the one change in this release whose fix is invisible in a plain-bash reading: the two forms are identical to a shell. `commands/pipeline.md` is a slash-command TEMPLATE, and the loader substitutes bare `$N` tokens in the text before a shell runs it, so a rendered copy could lose the arguments and exit 1 (INDETERMINATE) on every panel and frontend surface probe, which the caller reads as a broken probe rather than a broken template. **Until your installation refreshes, your sessions keep running the old form**, because `/pipeline` and the agent contracts are loaded from the installed plugin cache and not from your checkout; nothing in the repository re-syncs that cache on merge, and no check runs in that runtime, so nobody is notified when the window closes. The same applies to every enforcement claim the agent contracts and the two review schemas make in this release: they describe the source tree, and reach your sessions at your next plugin update.
14. **A Phase 2 `review.json` written before this release can BLOCK a `dba`, `devops` or `secops` stop for thirty minutes after you upgrade.** This release adds `must_satisfy` to the required list on review `concerns[]` items and `remediation` to SecOps `vulnerabilities[]` items. The SubagentStop validator checks those three agent types against TWO artifacts, not one: their own `review.<role>.json` shard AND the merged `review.json` at `/<role>`. The check is keyed to the STOP, so a merged Phase 2 record is re-read at every later stop of the same type while the file's mtime is inside the 30-minute recency window - which means a Phase 4 panellist can be blocked on a Phase 2 block it did not write. **Measured on this repository's own in-flight run:** `dba` 4 failures, `devops` 2, `secops` 5, all `missing required field "must_satisfy"` on `review.json`, with the other six roles silent in the same run. **Who this reaches:** only a run still in flight at the moment you upgrade, and only for thirty minutes per touch of that file; nothing revalidates `knowledge/issue-archive`, and an artifact older than the window is skipped. **What to do:** let the file age out of the window, or re-run the Phase 2 reviewer that owns the block. Do NOT backfill the field into another role's finished record - `''` satisfies it and writes a property nobody stated into a record that is about to be archived and committed. **Scale of the retroactive reach, so you can judge it before upgrading:** over one measured corpus of already-written artifacts, 17 of 229 vulnerability rows carry no remediation (7%), and on the concerns side 488 of the 488 rows the required list governs carry no `must_satisfy` at all (100%). If you would rather not meet this mid-run, upgrade between runs.
15. **Editing `pipeline.config.json` now forces the architectural tier unconditionally; item 2 above was quietly conditional until this release.** Item 2's guarantee actually depended on the project's own config listing that file under `architecturalTriggers.paths`, which only the shipped example config did; a project that copied the example and edited it, or carried no config at all, never got the promised trigger. It is now a hardcoded floor inside `ba.md` itself, so it holds with zero config content, and your own `architecturalTriggers.paths`/`.domains`/`.keywords` union onto the built-in list rather than define it (a config value can only add a trigger, never remove one). Nothing in code evaluates a diff against this rule, so `dev.md` and `secops.md` each gained a duty to self-report the mis-tier if either notices, mid-work or mid-review, that a non-architectural diff touches `pipeline.config.json` (#21).
16. **The Phase 0.5 blast-radius map requirement is enforced again, this time independent of tier, closing a gap the previous release opened.** Item 9 above made a tier-restricted phase-entry row abstain rather than refuse whenever the tier is not yet known. The `map.json` requirement lived on exactly such a row (`1-ba`, gated on `tiers: ["architectural"]`), and `1-ba` is always checkpointed BEFORE BA determines the tier, so that row could never actually fire on a run's first visit: an architectural-tier run that skipped Phase 0.5 and never produced a `map.json` passed the phase-entry guard at `2-review` with nothing to say about it. The `1-ba` row is untouched and still matters on a rework re-entry, once a tier is already recorded, but the real requirement now also lives on `2-review`, as a second check beside that row's existing approved-spec requirement. It needs no tier restriction of its own: `2-review` is a phase name only an architectural-tier run ever reaches, so the phase name itself is better tier evidence than the optional, sometimes-absent `risk_tier` field (#61).
17. **The no-secrets rule for `status.json` free text now covers all five fields it is committed and archived with, not just `ask_text`.** `events[].note`, `flags[].summary`, `veto_reason` and `error` are written by the orchestrator, committed to git, and copied verbatim into `knowledge/issue-archive/`, exactly like `ask_text` always was, and none of the four were named by the old rule. `error` is the sharpest: its natural content is copied machine output (a failed `gh`/`curl` call echoing a URL with a token, a database error carrying a connection string), which is exactly the shape a secret leaks in. This is a content rule, not a length one: beyond a pre-existing, unrelated 140-character digest bound already on `flags[].summary`, nothing here caps length, because a cap would refuse a field's correct work (a long note recording a real reproduction, say) without addressing the actual risk. A test suite now scans both the committed records and the archived copies for credential-shaped strings; if it fires on something already committed, the fix is to amend that commit, not to fix forward, since the exposure already happened in history either way (#52).
18. **A finished run's artifacts can no longer be silently archived stale.** The Phase 3-to-4 sync step used one blanket no-clobber copy for every artifact, which was only correct for the three files seeded before Dev starts (`spec.json`, `review.json`, `status.json`); it also froze the four files Dev and the panel produce IN the worktree (`map.json`, `tasks.json`, `impl-report.json`, `peer-review.json`) at whichever state was copied first, silently discarding any later fix, including one made during an APPROVE_WITH_NOTES nit round. The copy is now split by which side owns each file: the three seeded files still refuse to be overwritten, the four worktree-produced files now overwrite every time, and anything matching neither rule is copied on the safe no-clobber side and printed as unclassified so a new artifact type gets noticed instead of mishandled. Running the sync again right before archival is still only a written convention, not something enforced on itself, so the real backstop sits at archival: `archiveIssue` now compares each worktree-produced file against the worktree's own live copy and refuses to write the archive at all if they disagree, naming exactly which files diverged. It steps aside, neither checking nor refusing, once the worktree is already gone (routine post-merge cleanup makes this the common case) or when neither `tasks.json` nor `impl-report.json` recorded which worktree the run used. The one escape hatch is `PIPELINE_ARCHIVE_ALLOW_STALE=1`, which archives the stale copy anyway and says so on stderr (#58).


19. **Phase 4 panelists are now told, in their own contracts, that the shared dispatch worktree is READ-ONLY to them, and what an isolated tree has to be before it counts.** Isolation is owed by any panelist about to write a tracked file, not by the panel as a whole, so a reviewer that only reads is unaffected and stays where it is dispatched. A tree qualifies only when BOTH hold: `git -C <isolated> rev-parse --absolute-git-dir` EXITS 0 and DIFFERS from the dispatch worktree's own, AND `git -C <isolated> ls-files` exits 0 with a non-zero count. Not `--git-dir`, which prints a relative `.git` in a main checkout and so falsely refuses a real `git clone --no-hardlinks` while falsely admitting a tracked subdirectory of the dispatch tree; not `--git-common-dir`, which two linked worktrees share and which would therefore refuse `git worktree add --detach`, the mechanism the rule recommends. A `cp`/`tar`/`rsync` copy is not admitted, and what the check SAYS about one depends on your dispatch topology: where the dispatch tree is a linked worktree its `.git` is a FILE and a copy preserving it resolves to the SAME gitdir, so the check refuses it; where the dispatch tree is a main checkout that same copy is an independent repository and the check admits it. **A clone alone is not a pin** - it lands on the source's HEAD as it stands at clone time, and that tip moves inside a round, so pair it with `git -C <dest> checkout --detach <REVIEWED_SHA>`. **Location is stated as an outcome over the whole ancestor chain, not a blessed directory**, and as a disjunction: traversal needs other-execute on EVERY component, so one denying component denies the chain. Measure with the `ls -ld` walk the contracts carry rather than `stat`, whose format flags mean different things on BSD and GNU, or make the property true by construction with `install -d -m 700 <parent>`. **Two costs, named separately.** First, what you will SEE: a panelist that used to write in place now registers its own worktree, `git worktree list` grows, and nothing sweeps it - `git worktree prune` reclaims a registration only once its directory is already gone, so removal is the panelist's job and an agent cut off mid-run leaves one behind. Record the registry NAME rather than the path if you need to identify one later. Second, and this is the honest part: **nothing mechanically enforces any of it.** The rule is prose in nine agent contracts and in the `/pipeline` Phase 4 preamble; no hook, schema or test refuses a tracked write in the dispatch tree, and the commit-hygiene clause (`git status --porcelain` first, explicit paths only, never `git commit -a`/`add -A`/`add .`) is the one rule sited at the actual ship event and stops nothing either. Treat it as a stated standard a reviewer can be held to, not a control. Like item 13, it reaches your sessions at your next plugin update, because the contracts load from the installed plugin cache and not from your checkout (#19).
20. **The Stop-hook's voice check no longer re-fires for a decision it already forced you to explain, and can no longer be silenced by resending the exact message it just blocked.** The check decided whether a human turn had happened since it last fired from a single stale input, a `status.json` phase with no notion of who wrote it or when, so it re-imposed the full report shape on ordinary progress updates long after you had already been given the full context. The more serious half: its own refusal record satisfied its own definition of a human turn, so the control disarmed itself the instant it first fired, and resending the identical blocked message then passed. The boundary is now derived from the transcript itself and identified POSITIVELY (a record-level `origin.kind === "human"`, plus five guarded clauses on `type`/`isSidechain`/`isMeta`/`message.role`/`timestamp`) rather than by excluding known machine spellings, which is what had let the refusal record, background task-completion notices, and same-machine cross-session messages all pass as a person. Nine residuals are declared where the fix stops rather than chases a diminishing return, each with its own fail-direction and expiry written into the module header. The sharpest is a narrow, permission-error-only silent gap on the fallback status-resolution path (`EACCES`/`EPERM`/`EIO` on a foreign lane's `status.json`, not the common and correctly-silent case of a file archived out from under the scan mid-turn): left declared rather than forced closed, because the only mechanical fix moves the same silence to a different line instead of removing it. `resolveStatus` now returns `{status, dir, mtimeMs}` instead of a bare status object, and `isHumanTurnRecord` is newly exported; neither has an external importer today. Like items 13 and 19, this reaches your sessions at your next plugin update: `voice-lint.mjs` is a script your installed cache serves, not something re-read from your checkout on every Stop (#56).

21. **`spec.falsifiability_pass` is machine-checked now, and `/pipeline` no longer claims more than it checks.** The orchestrator has said for this block's whole life that "the table is machine-checked against the criterion list so the two cannot drift". Nothing checked it: `falsifiability_pass` appeared in ZERO scripts, and it sits outside `spec.schema.json`'s top-level `required`, so a spec could omit the block entirely and still validate. `groundFalsifiability` in `scripts/validate-pipeline-artifact.mjs` now runs on every `spec.json` the SubagentStop validator sees. **What it enforces is COVERAGE and only coverage:** every `AC<n>`-labelled acceptance criterion carries at least one row in `one_mutation_per_criterion` or `unmutable`, and at the architectural tier the block is present at all. Below that tier it fails open. **Three things are deliberately NOT refused**, decided by running the rule against the nine archived specs rather than from first principles, because a stricter gate would have refused five of the nine for doing good work: extra rows naming a residual or a premise rather than an AC (four archived specs use them on purpose), a criterion appearing in BOTH lists (#19's AC4 is partially unmutable, with the reason written down), and unlabeled criteria, which make the check ABSTAIN and say so rather than report a clean it did not measure. **Label your criteria `AC1. ...` or this gate enforces nothing** — it tells you when that happens. The failure is advisory in the SubagentStop sense the rest of that validator uses: a `{decision:"block"}` object on stdout, exit 0, asking the agent to fix the artifact before finishing. It reports nothing on all nine archived specs, so it costs existing work zero; it exists for the state the archive cannot show, every archived spec being a FINAL one — a spec REVISION that adds a criterion and no row for it.

22. **`review_rounds` is cross-checked against the events it summarizes, because it was wrong far more often than not.** The counter is hand-incremented by the orchestrator at the phase-4 checkpoint. Across this repo's seven committed records it disagreed with the observable round count on FIVE, in BOTH directions: one records 4 against 2 real panels, one records 1 against 3, and two record 1 having never entered phase 4 at all. ## The gates (portable disciplines, kept from the original)

- **Blast-radius map** — before the spec locks, enumerate the contracts/types a change touches and their readers, so Phase 4 verifies unchanged consumers instead of discovering the regression later.
- **Grounding gate** — any directive about how a field is handled must first cite the field's real persisted shape (nullable? default? omitted on the common path?). A fail-direction call made without that grounding is invalid.
- **Gate-bites proof** — when a change adds a build-failing control (a lint rule, a CI check, a gate), it is not done until you have recorded the control failing on a planted violation and passing on the fix. A control no one has watched fail is indistinguishable from a no-op.
- **Config doctor** — every knob here fails soft: a missing key takes a default, a misspelled key is ignored, a wrong-typed value falls back. Correct at runtime, and exactly why a broken config is invisible. The session-start warmup now reports what is missing, what is misspelled (with the nearest real key and the script that would have read it), what is the wrong type, and what silently stops working as a result. It stays quiet when the config is fine. This plugin's own shipped example carried the bug it catches: `migrationsGlob` where the code reads `migrationGlobs`, and a string where it requires an array, so anyone who copied and edited it kept the default forever.
- **Voice lint** — `voice.md` was referenced twelve times in `pipeline.md` and four in `phase.md`, and until now nothing read it, which is rule 19 of `evidence-controls.md` about its own author: a written expectation no code reads is a comment. The Stop hook now derives whether this is a full-voice moment from `status.json`'s `current_phase` rather than asking the orchestrator to remember, and checks the message's shape (decision block, rating scales, the replication block, no em dashes, no "as discussed"). It is silent on every stop that is not a pipeline voice moment, deliberately: a lint that enforced the em-dash rule on ordinary conversation would be switched off within a day. It checks shape, never quality. And it stops at the owner boundary: it runs on Stop, never SubagentStop, because `voice.md` is a handoff protocol for the one moment a human has to decide something, not a house style. Agents talk to each other in their own dense, technical register, and that traffic is never linted.
- **Open-questions gate** — BA records genuine ambiguity in `spec.open_questions` with a recommendation instead of inventing an answer, and a `blocking` entry halts Phase 1 until the owner answers. It is a typed field and not an instruction because `requirements` and `acceptance_criteria` are schema-required: before it existed, a spec with a blank failed validation while a spec with a plausible guess passed, so the contract paid BA to guess. `blocking: true` has to clear two bars, not one: name two acceptance criteria that follow from two answers, AND the difference between them must be one only the owner can settle (cost, timeline, reversibility, product direction). Falsifiability alone lets engineering-internal questions through, and a gate that fires on those is a gate that gets switched off.
- **Design-lock** — the bake-off's two sketches get opposing assigned stances (smallest blast radius vs. cleanest seam), because separate contexts alone do not make two samples of one model independent. When the judge rules that they materially diverged, the choice goes to the owner as a decision block before Phase 3 starts. This is the only standing owner gate on the happy path, placed at the moment with the lowest reversibility and the highest owner-only content (roadmap, urgency, what else is landing here).
- **Phase-entry guard** — phase sequencing used to be a norm: the orchestrator decided what ran next, so an orchestrator that skipped a phase was caught by nothing. The Stop hook now refuses to END a turn whose `current_phase` names a phase with an absent prerequisite. Completion is never written and never claimed, it is DERIVED: `spec.json`, `review.json`, `design.json`, `impl-report.json` and `peer-review.json` exist only because a subagent was dispatched and returned, so they cannot be produced by omission. Everything but `status.json` is gitignored, so a resumed run on another machine has no artifacts at all; a committed `events[]` entry closing the phase satisfies the guard too, and writing a false one is an affirmative act in a committed, archived file rather than an omission. That is the threat model: omission, not forgery. It fires at the turn boundary, not before a dispatch, so it does not make skipping impossible — it makes an unrecorded skip become a blocked turn or a recorded one. It caught its own author: the run that built it had skipped the design bake-off without recording it, and refused itself until the deviation was written down.
- **Phase 4 tracked-write gate** — a `PreToolUse(Bash)` hook refuses a SUBAGENT's blanket staging (`git commit -a`, `git add -A`, `git add .`, `git add -u`, `git stage -A`, and every bundled spelling of them: `git commit -aqm 'm'` and `git add -Av` stage exactly as much and are refused too) while an in-flight run sits at a Phase 4 phase, so the commit-hygiene rule the agent contracts carry is enforced at the tool call instead of argued at the reader. It is scoped by ORIGIN and not by role: only a call carrying Claude Code's `agent_id` field is in scope, so the orchestrator's own status-only checkpoint is exempt by design, and there is no role allowlist — which makes it deliberately WIDER than the panel, and a subagent that is not a pipeline panelist at all (a general-purpose Task worker, an adopting project's own agent) is refused too whenever a Phase 4 run is the resolved owner. Explicit-path staging is never refused, whatever the path, including `git add -u <path>` and a panelist's own `.pipeline/<issue>/peer-review.<role>.json` shard; a forbidden spelling quoted inside a commit MESSAGE is not an invocation and is not refused. It fails OPEN on every tooling gap, and it abstains whenever it cannot tell whose run a call belongs to, writing one line to stderr that names which gap or abstention it was. `CLAUDE_HOOK_PRETOOLUSE_SKIP=1`, set in the environment the hook itself runs in, disarms it for a session — and unlike the phase-entry guard above that is allowed, because the carve-out refusing an opt-out knob covers HALTING controls and this is a ratchet that already fails open by construction, but operating it still leaves its own distinct line on stderr, since the carve-out's reason (a suppression that leaves no trace in the archived record) binds on either side of it.
- **Materiality** — every review concern carries `likelihood`, `reversibility` and `harm` beside its severity, and only a blocker/critical/high concern that is reachable in normal use (or adversarial AND irreversible or data-harming) may block a merge; a hypothetical never does. `scripts/materiality.mjs` is the rule in code and `merge-peer-review.mjs` applies it to every shard it folds, so a `REQUEST_CHANGES` with no blocking concern is recorded as `APPROVE_WITH_NOTES` with the reviewer's own verdict kept beside it. Notes ship: a note with a `suggested_patch` is applied by the orchestrator in the same turn, a note without one is filed as an issue. At most two blocking concerns per reviewer. The SecOps `VETO` stands only on a named `veto_ground` from the enumerated security surfaces. Measured reason, from this repo's own archive: first-pass approval on 4 of 11 runs, Phase 4 the largest consumer of run time, every finding real and most of them unreachable by any user.
- **One fix round by default** — a delta re-review that returns `REQUEST_CHANGES` again stops and puts re-open / defer / proceed to the owner. The delta round itself seats only the objecting roles plus whoever's surface the fix touched: SecOps on security or data-layer paths, QA on test files, DBA/DevOps/Design on theirs. Nobody is re-seated unconditionally.
- **Mis-tier tripwire** — a migration/auth/contract-shape change appearing in a standard-tier diff halts and re-tiers to architectural. The deep gates cannot be skipped by mis-classifying an ask.
- **Live-verification gate** — for data-migration or security-sensitive changes, a self-skipping integration suite that skips when its env is absent does not count as verification; a recorded local pass is required.
- **Frontend visual-verification gate** — a frontend-touching diff needs recorded design evidence (a design review verdict + lint + accessibility pass) before the panel.

## Artifacts

Every phase writes typed JSON under `.pipeline/<id>/` in your project (add it to your `.gitignore`; keep `status.json` if you want cross-machine resume). Schemas are in [`schemas/`](schemas/). The validator is a SubagentStop hook, not a general-purpose CLI: it reads the hook payload on stdin and validates the stopping agent's artifact, so it takes no `<type> <file>` arguments. Its only flag is `node "${CLAUDE_PLUGIN_ROOT}/scripts/validate-pipeline-artifact.mjs" --self-test`, which runs its built-in checks.

**Naming a run directory, and how to tell the gate is alive.** The validator only recognises a run directory named `<issue-number>` or `exp-<slug>`, because those are the two names `ba.md` sanctions. A run named any other way — which is what you get when `gh issue create` fails outside experiment mode — used to opt out of every artifact check in silence. It no longer does: such a directory is still validated when it is the only run in the project, and the validator says so. More generally the validator now writes **one line to stderr on every stop**, naming the agent, the verdict (`checked`, `no-rules`, `no-active-issue`, `unnamed-run`, `unnamed-run-ambiguous`), the run directory and the violation count, so "I checked and it was fine" and "I never checked" are no longer the same observation. `decision:block` on stdout is unchanged. The one case that stays completely silent is a project with no `.pipeline/` directory at all — an ad-hoc, non-pipeline session must not be taxed a line per subagent stop.

## Tests

The four hooks have a dependency-free bash suite (no framework, no `node_modules`):

```
bash plugins/pipeline/tests/run.sh
```

There is no hosted CI for the suite (0.40.2 retired the Actions workflow: forty minutes per push, billed to a subscription). The Linux answer is taken on demand, in a pinned container, with the strict-capability flag set so an absent optional tool such as zsh counts as a failure rather than a silently narrower suite:

```
bash plugins/pipeline/tests/run-linux.sh                 # the whole suite
bash plugins/pipeline/tests/run-linux.sh test-x.sh ...   # named suites
```

It builds throwaway git repos and drives each hook end to end: that the Stop hook blocks a turn (exit 2) on a failing check and stays out of the way otherwise, that the SessionStart report degrades quietly outside a repo or with a broken config, that the SubagentStop hook passes a `decision: block` through while fail-opening on every tooling gap, and that the PreToolUse gate denies a Phase 4 subagent's blanket staging, allows explicit-path staging and the orchestrator's own checkpoint, and fails open on all eight of its tooling gaps.

Each config-parsing case was recorded FAILING against the pre-fix hooks before it was recorded passing, per the gate-bites rule below. A control nobody has watched fail is indistinguishable from a no-op, and that is not hypothetical here: both hooks previously read `pipeline.config.json` with a regex that silently returned the default on a reformatted config, so the Stop hook's check gate could stop firing with nothing to indicate it had.

This repo's own [`pipeline.config.json`](../../pipeline.config.json) wires that suite as `checkCommand`, so the Stop hook gates development of the plugin with the plugin's own machinery.

## Requirements

- Claude Code with plugin support.
- Node (for the bundled scripts) and git.
- Optional: the GitHub CLI (`gh`) if you want the pipeline to open issues/PRs. Without it, the tracker steps degrade to local notes.
- Optional, and only for frontend work: a **preview/browser MCP server** of your own choosing. This plugin ships none and declares none. The `design` and `art-director` agents list Claude Preview's tools in their frontmatter as one option (`# CUSTOMIZE`); swap in whatever your project uses. Without one, `design` can still run its token-lint lens through `Bash`, but it CANNOT run axe-core, so it records `a11y: { status: "unavailable" }` rather than a pass and `gate-pre-phase4-frontend.mjs` correctly halts a frontend-touching diff instead of passing one on evidence nobody gathered. `art-director` cannot render at all, so it holds no binding ground and degrades to advisory. Both are instructed to name the missing tool, so the halt is diagnosable; neither is permitted to record an unrun check as a pass.
